# Architecture v0

**Date:** 2026-08-17  
**Status:** proposed, deliberately small and reversible

## Decision summary

Build a local, file-first demonstrator in Python with a deterministic analytical core. Use a thin FastAPI boundary and Streamlit interface only after the core is proven by tests. LLM integration is optional and isolated behind a provider-neutral interface.

## Logical flow

```text
Excel workbooks
  -> ingestion (schema recognition + immutable source IDs)
  -> validation (deterministic findings / gating)
  -> canonical dataset
  -> reconciliation (Actual/Budget/Forecast; period and YTD)
  -> variance ranking + drill-down
  -> lineage/evidence bundle
  -> explanation adapter (optional, constrained)
  -> UI: analysis + evidence + Approve/Correct/Reject
```

## Components

| Component | Responsibility | v0 choice |
|---|---|---|
| `src/ingestion` | Read workbook, identify sheet/columns/types, attach source row identifiers | Python + Pandas + openpyxl |
| `src/validation` | Deterministic quality checks and blocking findings | pure Python/Pandas |
| `src/reconciliation` | Canonical Actual/Budget/Forecast comparisons | pure Python/Pandas |
| `src/analytics` | Rank deviations and calculate drill-down contribution | pure Python/Pandas |
| `src/agents` | Convert computed evidence into bounded language and recommendations | provider-neutral protocol; no external call initially |
| `src/api` | Stable programmatic API after core is verified | FastAPI |
| `src/ui` | File upload, findings, drill-down, evidence and human feedback | Streamlit |

## Canonical data contract (initial)

A canonical record represents one actual transaction or one planned allocation. Required business fields are `scenario`, `period`, `amount`, `currency`, `account`, and `cost_center`; all inputs also retain `source_file`, `source_sheet`, `source_row` and a deterministic `record_id`. Optional dimensions include business unit, product/material, supplier, purchase order and forecast-freeze flag/date.

## Trust boundaries

1. **Input boundary:** uploaded files are untrusted; validate file type, size, worksheets, headers and formula handling.
2. **Calculation boundary:** no LLM or UI value may enter computed outputs.
3. **Model boundary:** only aggregate, relevant evidence may leave the application; raw source rows and secrets are excluded by default.
4. **Presentation boundary:** every displayed conclusion references an evidence object generated by the core.
5. **Human boundary:** generated recommendations require explicit approval and are not executed.

## Deferred decisions

- PostgreSQL: add when persistence and multi-user work are evidenced.
- Docker: useful for reproducible demos, but not available locally and not required for the first tested core.
- authentication/multi-tenancy: do not build before a legitimate pilot requires it.
- direct integrations: only after file-first workflow validation.
- external LLM provider: only after deterministic demo and a data-handling decision.

## Technology rationale

Pandas and openpyxl are boring, transparent choices for an Excel-first MVP. FastAPI provides a clean API boundary; Streamlit gives a fast reviewable interface without premature frontend complexity. Python business logic stays independent of both interface and model provider.
